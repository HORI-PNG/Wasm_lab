# 理解の確認（問題）

ステップが終わって説明したら、Claude がユーザーに問題を出す。**全問に正しく答えられたら合格**とし、合格してから次のステップの計画の承認に進む。

問題の作り方・採点・記録の詳しい手順は、skill **`step-quiz`**（`.claude/skills/step-quiz/SKILL.md`）に従う。ユーザーは `/step-quiz step01` のように呼び出して、好きなときに問題を出させることもできる。

### 問題の作り方

- 1 ステップにつき **5〜8 問**。次の 3 種類をすべて含める。

  | 種類 | 例 |
  |---|---|
  | 何をしたか | 「このステップで `mainClass` を何から何に変えたか。それで何が変わったか」 |
  | 技術的な質問（なぜ・仕組み） | 「JVM との一致だけでなく、数学的な性質も確かめるのはなぜか」 |
  | 実行内容（コマンドと結果の読み方） | 「`verify-tools/run.sh` の終了コードが 1 のとき、どこを見れば原因が分かるか」 |

- 答えを丸暗記しなくても、そのステップの内容を理解していれば答えられる問題にする。数値や名前をそのまま問うだけの問題は少なめにする。
- 記述式を基本とする。選択式を混ぜてもよい。
- 問題を出す前に、答えを `quiz.md` に書かない（ユーザーがファイルを見ると答えが分かってしまうため）。

### 進め方

1. 問題を `logs/stepNN-内容/quiz.md` に書き、チャットでも示す。
2. ユーザーが回答する。
3. Claude が 1 問ずつ判定し（正解・一部正解・不正解）、それぞれに解説を付ける。
4. 一部正解・不正解の問題は、解説の後に**言い方を変えた問題**を出し直す。正しく答えられるまで繰り返す。
5. 全問正解になったら合格。`quiz.md` に問題・回答・判定・解説を記録し、`logs/README.md` の状態を「理解の確認済み」にする。
6. 合格してから、次のステップの計画（`next-plan/`）の承認に進む。
