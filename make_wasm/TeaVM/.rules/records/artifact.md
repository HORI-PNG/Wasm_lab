# 記録（`logs/stepNN-内容/Artifact.md`）

1 ステップにつき 1 フォルダを作り、その中に `Artifact.md` を置く（Antigravity の Artifact に倣った形）。

```
logs/
├ README.md                     … ステップの一覧（ブランチ・状態）
└ stepNN-内容/
   ├ Artifact.md               … このステップの記録（下の形式）
   ├ plan.md                   … 承認されて実行した計画（next-plan/ から移したもの）
   └ quiz.md                   … 理解の確認の問題と、ユーザーの回答・判定（[`../workflow/understanding-check.md`](../workflow/understanding-check.md) 参照）
```

`Artifact.md` は次の形式で書く。

1. **概要**：何をしたか（3 行程度）。ブランチ名・日付・承認の有無
2. **タスク**：チェックリスト（終わったものに `[x]`）
3. **実装計画**：どう進めたか、なぜそうしたか
4. **ウォークスルー**：実際にやったこと、実行したコマンド、途中で直したこと
5. **変更したファイル**：ファイルと変更内容の表
6. **検証結果**：何をどう確かめ、どうなったか（失敗も書く）
7. **分かったこと・残った課題**：次のステップに引き継ぐこと
8. **確認用コマンド**（必ず最後に置く）：ユーザーが自分で結果を確かめるために実行するコマンドのまとめ
   - 実行する場所（例：`make_wasm/TeaVM` フォルダ）を最初に書く。
   - コマンドは 1 つずつ別のコードブロック（` ```bash `）に書き、それぞれ「何を確かめるコマンドか」と「期待する結果（どう表示されれば OK か）」を添える。
   - 実行の順番に並べる（例：ブランチの切り替え → ビルド → 検算 → 結果のファイルを見る）。
   - 時間がかかるコマンドは、その目安も書く。

- 作業の途中でも更新する。最後にコミットに含める。
- `logs/README.md` のステップ一覧も更新する。
