- 判定：一部正解
- 解説：目的（WebGPU と CPU の速さ比べの計測）、対象（手書き版にしかない関数）、やり方（YAML に書き、生成器が公開窓口に足す）は合っています。生成物の変化は、`NfcWasm.java` の最後に **3 つのメソッド**（17 行）が足されただけです。**`nfc.generated.js`（JS ラッパー）は変わっていません**（決めてほしいこと b① で「JS ラッパーには入れず、wasm の関数を直接呼ぶ」に決めたため）。JS からは `exports.multiply(…)` のように直接呼びます。

- 判定：不正解
- 解説：問題文が分かりにくくてすみません。比べてほしかった 2 つのやり方は、(A) 自動生成された `NfcWasm.java` をエディタで開いて、計測用の 3 つのメソッドを手で書き足す、(B) `codegen/nfc.yaml` の `extra_exports` に 3 つを書く（step03 のやり方）、です。(A) は、生成器をもう一度動かすと `NfcWasm.java` が丸ごと書き直されるので、手で足した 3 つは**消えます**。(B) は、生成器が毎回 YAML を読んで 3 つを書き直すので、**なくなりません**。

## 問題 4（B. 技術的な質問）

`prepareMultiply` と `multiplyPrepared` は、step01〜02 の自動生成のルール（NFC の入口クラスを見つけ、引数と戻り値の型を変換して呼ぶ）では作れません。
なぜ作れないのですか。この 2 つの関数が何をしているかに触れて答えてください。

- 回答：prepareは、2次元を1次元+行・列に変換する独自の関数であるため、引数がルール外である。Preparedは、それを2次元配列に戻す関数であるため、これも引数がルール外である
- 判定：不正解
- 解説：2 つの関数の働きが違います。`prepareMultiply` は、JS から受け取った行列 A と B を、Java 側の変数（`MatrixWasm` の `preparedA`・`preparedB`）に**しまっておく**関数です。`multiplyPrepared` は、引数なしで呼ばれ、しまっておいた A と B で**積の計算だけ**をします。自動生成のルールが作れるのは「NFC の入口クラスのメソッドを 1 回呼んで、その場で答えを返す」関数です。この 2 つは NFC のメソッドではなく、しかも**呼び出しをまたいで値をしまっておく（状態を持つ）**ので、ルールでは作れません。なお、2 次元配列 ↔ 1 次元配列の変換は、自動生成のブリッジも普通に行っていて、ルールの範囲内です。

## 問題 5（B. 技術的な質問）

step03 では、手書きの `MatrixWasm`（クラスと 3 つのメソッド）に `public` を付けました。
付けなかったら、何が起きますか。理由もあわせて答えてください。

- 回答：つけなかったら、エントリーポイントの自動生成ルールに入らないため、Wasmが作成されず、JSから実行できない
- 判定：不正解
- 解説：「自動生成のルールに入らない」からではありません。`public` が付いていないクラスやメソッドは、**同じパッケージの中からしか呼べません**。`MatrixWasm` は `org.example` パッケージ、自動生成の `NfcWasm` は `org.example.generated` パッケージなので、別のパッケージです。`public` がないと、生成された `NfcWasm.java` の `org.example.MatrixWasm.multiply(…)` という呼び出しが**Java のコンパイルエラー**になり、`./gradlew :app:build` 自体が失敗します（Wasm が 1 つもできなくなる）。

## 問題 7（C. 実行内容）

`build/verify/report.md` の「関数ごとの結果」の表を見ると、`multiply` と `multiplyPrepared` の行は、3 種類の入力（general・spd・rect）すべてが「例外（一致）」でした。

- 判定：一部正解
- 解説：(1) 検算の失敗ではない、は正解です（JVM・Wasm の両方で同じように例外になり、「一致」と判定されている）。(2) は違います。`multiply` は、`JvmReference` が引数を型の並びから決めるときに、`b, bColumns` の `b` を「後ろに `int` が 1 つしかないのでベクトル（長さ 8）」とみなしてしまい、行列の大きさが合わずに例外になります。`multiplyPrepared` は、名前順で `prepareMultiply` より先に呼ばれ、まだ行列がしまわれていないので例外になります。(3) は、`wasm-verify.mjs` に足した**数学的な性質のチェック**（Wasm の `multiply` の答えが、JS で計算した `A·B` と誤差 0 で一致するか、など 3 項目）と、JVM 上での**手書き版との比較**で確かめています。

### 問題 7''（問題 7' の書き直し）
